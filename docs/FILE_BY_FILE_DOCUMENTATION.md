# Varma Xerox — File-by-File Documentation

A Next.js 15 multi-operator print workstation & document generator for legal/business documents.  
Stack: React 19, Next.js 15, Zustand, Drizzle ORM, Neon PostgreSQL, Tailwind CSS 4, docx.js, jszip.

### `app/api/export-docx/route.ts` (693 lines)
**Purpose:** POST API route that generates downloadable `.docx` files for each template.

**Two approaches used:**

1. **Template-based (ZIP injection)** — For CDMA, Lease Deed, SBI Alias, Single Women Affidavit:
   - Reads a pre-existing `.docx` template from `public/templates/`
   - Opens it as a ZIP, extracts `word/document.xml`
   - Replaces `{{placeholder}}` tokens with form values (XML-escaped)
   - For CDMA: Also handles checkbox toggles (☐ → ☑) based on Yes/No/radio selections
   - Re-zips and returns as binary download

2. **Programmatic generation (docx.js)** — For CV, Identity Card, Affidavit, Rent Agreement, and fallback:
   - Builds a `Document` object using the `docx` library's `Paragraph`, `TextRun`, `Table`, etc.
   - Packs to buffer via `Packer.toBuffer()`
   - Returns as binary download

**Fallback:** Any unrecognized template type gets a generic field dump into a `.docx` file.

## `lib/docx/` — DOCX Template Engine

This is the structural document template engine that compares blank vs. filled `.docx` files to create tokenized templates.

---

### `lib/docx/tokenize.ts` (224 lines)
**Purpose:** Low-level XML tokenizer for WordprocessingML parts. Parses `<w:p>` paragraphs and `<w:t>` text runs without flattening — preserves byte offsets for in-place editing.

**Key exports:**
- `tokenizePart(xml)` → `TokenizedPart` with paragraphs (each containing runs with byte offsets)
- `decodeXmlText(s)` / `encodeXmlText(s)` — XML entity handling (`&amp;`, `&lt;`, numeric entities)
- `replaceRunText(xml, run, newText)` — Replaces text content of a specific run in-place, handles `xml:space="preserve"`
- `extractStructure(xml)` — Splits XML into tables and non-table paragraphs

---

### `lib/docx/diff.ts` (298 lines)
**Purpose:** Run-level structural diff engine — compares blank and filled DOCX parts to produce a tokenized template.

**Algorithm:**
1. Tokenize both blank and filled parts
2. For each paragraph pair, align runs via monotonic walk with bounded window-LCS
3. Where blank run text differs from filled run text, replace with `{{field_name}}` token
4. For checkbox groups (☐/☑ glyphs), create a single checkbox field with per-position tokens
5. Apply all edits in descending byte-offset order to maintain validity

**Output:** `DiffResult` with fields[], modified parts, field keys

---

### `lib/docx/html.ts` (122 lines)
**Purpose:** Builds an HTML skeleton from DOCX XML for on-screen preview. Extracts font styling (bold, italic, underline, size, color), paragraph alignment, indentation, spacing, tables, and preserves `{{token}}` markers inside `<span data-f="...">` elements.

---

### `lib/docx/render.ts` (107 lines)
**Purpose:** Hydrates a stored template `.docx` with operator values. Replaces `{{token}}` placeholders in the raw XML `<w:t>` runs with actual values. Handles checkbox groups (positionTokens → ☑/☐).

Two entry points:
- `renderDocx(templateZip, values, fields)` — Full ZIP round-trip (server-side .docx output)
- `renderParts(parts, values, fields)` — In-memory parts-only rendering (for preview)

---

### `lib/docx/template.ts` (52 lines)
**Purpose:** High-level orchestrator — builds a complete structural template from blank + filled .docx files:
1. Opens both ZIPs, reads XML parts
2. Runs `buildDocxTemplate()` diff
3. Builds HTML skeleton from the diffed parts
4. Patches blank ZIP with tokenized parts → template .docx

---

### `lib/docx/zip.ts` (45 lines)
**Purpose:** Minimal .docx ZIP read/write helpers built on jszip:
- `openDocx(buf)` — Load buffer as JSZip
- `readPartText(zip, name)` / `readPartBuffer(zip, name)` — Read specific XML parts
- `xmlPartNames(zip)` — List all .xml files in the ZIP
- `writeDocx(zip, patch?)` — Serialize back to Buffer, applying optional patches, with DEFLATE compression

|---|---|

| `lease_deed_template.docx` | Tokenized lease deed template with `{{placeholders}}` |

| `sbi_alias_general_template.docx` | Tokenized SBI alias declaration template |
| `single_women_affidavit_template.docx` | Tokenized single women welfare affidavit template |
| `cdma_logo.png` | MeeSeva logo image — embedded in the CDMA form header when rendering the template |

**Template workflow:** A `_raw.docx` (filled) is compared against a blank `.docx` by `diff.ts` → produces a `*_template.docx` with `{{tokens}}` → `render.ts` hydrates tokens with actual values at export time.
